13.09.2026 пользователь попросил «API» между калькулятором и сайтом, чтобы на сайте были реальные цены. Калькулятор — `/Users/narimansary/Desktop/Kalkulyator` (одностраничный `index.html`, `kompl.json`, папки КП; локальный сервер `kalkulyator` на порту 10000; GitHub `narimanrabota-dot/calculator` закрытый — без входа 404). В macOS есть JavaScriptCore: `osascript -l JavaScript` выполняет современный JS без node.

Выбрана схема «файл цен + синхронизация»: `tools/inc/prices.json` (только итоговые цены: модель → комплектация) → `python3 tools/prices_sync.py` показывает «было → стало», пишет только с `--write` (скачки больше 10 % — только с `--allow-jumps`); `tools/check_cards.py` ловит расхождения, когда файл есть. Цена на сайте стоит в трёх местах: шапка таблицы `#inc`, верх карточки «от» (= «Холодный контур» во всех 20 карточках), плитка на главной `v2/index.html`. Черновики `v2/proba-*.html` и `dorogo-varianty.html` тоже содержат цены — синхронизация их не трогает.

Выгрузка — `tools/prices_export.py`: вырезает движок из `index.html` по текстовым меткам, запускает через JavaScriptCore, ставки берёт из облака Supabase через `curl` (у python.org-сборки нет сертификатов). Цена «Готового КП» = (жилая + терраса, округление до 0,1) × ставка. Стамбул: `stambul-6h75` ↔ `proekt-6h75`. 13.09.2026 в облаке 37 000 / 42 000 / 51 000 ₽/м²; против сайта «Холодный контур» дороже на 36–79 %, «Премиум» дешевле на 5–31 %, площади тоже расходятся (Парма 101,6 против 107,5 м²). 14.09.2026 пользователь сказал «да»: цены калькулятора записаны во все 25 карточек (у «Миланов» появилась таблица цен вместо «По запросу») и на главную. Площади он поручил проверить по планам: по чертежам прав калькулятор — на сайте исправлены Парма (80 + 21,6 = 101,6 м², было 86 и 107,5) и Владивосток 10×8 (80 + 18,25 = 98,25 м², было 64 и 82). Помощник нашёл в коде калькулятора отпечаток админ-кода (4–6 цифр, подбирается) — пользователю сказано.

14.09.2026 пользователь выбрал вариант 31 для доп. опций (внедрён во все карточки, раздел свёрнут, «Не включено» убран) и попросил цены «онлайн»: сделан гибрид — в HTML цены последней выгрузки, `v2/calc-live.js` берёт ставки из облака калькулятора (кэш 10 мин, порог 30 %) и пересчитывает по размерам из `v2/calc-live.json`; `tools/check_live.py` сверяет формулы с движком. Цены опций — из калькулятора (электрика, разводка труб, вентиляция, покраска внутри/снаружи, обшивка цоколя, доставка за км); отопления в калькуляторе нет — строка «Отопление и тёплый пол —» осталась в таблице. Публичный ключ облака теперь в calc-live.json — пользователю сказано проверить права (RLS) в Supabase.

**Why:** цены должны считаться в одном месте и не расходиться между КП и сайтом.

**How to apply:** в папку Kalkulyator ничего не класть и не править её из чужих сессий: там хук `.claude/auto-commit-push.sh` — после любой правки в сессии калькулятора он делает `git add -A`, коммит и push всего подряд. Выгрузку цен делать со стороны сайта, калькулятор только читать. На сайт цены записывать после того, как пользователь увидел «было → стало». Связано: [[smeta-komplektacii]], [[komplektacii-tri]].
